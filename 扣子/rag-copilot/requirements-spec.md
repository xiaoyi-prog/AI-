## 1. 产品概述

### 1.1 产品名称

**PharmaRAG - 研发知识库 RAG Copilot**

### 1.2 产品愿景

构建生命科学研发领域的智能知识助手，让每一位研发、质量、法规人员都能在数秒内获得来自权威知识库的、可溯源、可信赖的精准答案，将"找文档、读文档、用文档"的效率提升一个数量级，同时严格保障文档安全与合规要求，最终成为企业研发知识资产的核心入口与信任基石。

### 1.3 目标用户

| 角色 | 职能 | 核心知识诉求 |
|------|------|-------------|
| 研发科学家 | 药物发现、临床前研究、实验设计 | SOP、实验方案、技术文献、内部实验记录 |
| 质量保证专员（QA） | GMP 合规、偏差管理、质量体系运维 | GMP 规范、偏差处理流程、CAPA 流程 |
| 法规事务专员（RA） | 注册申报、法规跟踪、合规策略 | ICH/FDA 指南、注册申报要求、法规动态 |

### 1.4 核心价值主张

PharmaRAG 为生命科学研发团队提供以下核心价值：

1. **精准溯源**：每一个答案都附带知识库原文引用与定位，答案可追溯、可审计、可验证，消除"AI 不知道从哪编出来的"信任障碍。
2. **权限安全**：基于文档级 ACL（访问控制列表）实现细粒度权限隔离，研发、质量、法规角色各只能检索到其授权范围内的文档，知识共享与信息隔离并行不悖。
3. **拒答而非幻觉**：通过置信度网关机制，当检索结果不足以支撑可靠回答时，系统主动拒答并转人工处理，宁可不说也不乱说，守住生命科学领域对信息准确性的底线要求。
4. **持续评测**：内置完整的离线评测与在线监控体系，以 Recall@5、MRR、NDCG@10、引用正确率、幻觉率、答案忠实度等量化指标驱动系统迭代，让每一次改进都可度量。

### 1.5 业务背景与痛点

生命科学研发是一个高度知识密集、强合规约束的领域。在日常工作中，研发、质量、法规人员面临以下核心痛点：

**痛点一：知识分散，检索效率低下**
企业内部知识分散在 SOP 管理系统、实验记录本系统（ELN）、文档管理系统（DMS）、法规情报库等多个异构系统中。一个研发科学家想确认"某化合物稳定性研究的 SOP 要求"，可能需要跨 3-4 个系统检索，耗时 15-30 分钟才能找到准确条款。FDA/ICH 指南等外部文献更是分散在多个官网，检索与阅读成本极高。

**痛点二：通用 AI 工具不可信**
通用大语言模型在回答生命科学专业问题时，常出现"看似合理实则编造"的幻觉现象。在法规合规场景下，一个错误的 GMP 条款引用可能导致严重的合规风险。研发人员无法信任通用 AI 给出的答案，因为这些答案没有权威来源支撑，也无法溯源验证。

**痛点三：权限隔离与知识共享的矛盾**
生命科学企业对文档权限有严格要求：研发部门的核心实验数据不能被法规部门随意查看，反之亦然。但传统的权限系统使得跨部门知识检索变得困难——用户不知道哪些文档自己有权访问，也不知道某个问题应该去哪个文档库找答案。

**痛点四：缺乏系统化的知识问答质量度量**
现有的知识检索工具（如全文搜索）没有质量度量体系。检索结果好不好、答案准不准，全靠用户主观判断。系统迭代缺乏量化依据，改进效果不可验证，导致系统长期停留在"能用但不好用"的状态。

**痛点五：合规审计要求未满足**
21 CFR Part 11 要求电子记录系统具备审计追踪能力。现有的知识检索工具大多没有完整的操作日志，无法满足"谁在什么时间查询了什么、得到了什么答案"的合规审计要求。

PharmaRAG 正是为解决以上痛点而生：通过 RAG（检索增强生成）架构，将企业内部知识库与公开生命科学语料统一索引，以带引用的答案合成消除幻觉风险，以置信度网关守住准确底线，以文档级权限控制保障信息安全，以完整评测体系驱动持续迭代，以审计日志满足合规要求。

## 3. 用户故事与验收标准

### 3.1 意图路由

#### US-IR-01：意图自动分类

**As a** 研发科学家（Dr. Chen），
**I want** 系统能自动识别我的问题是 SOP 查询、法规查询还是文献查询，
**so that** 我无需手动选择知识库分类，系统能将我的问题路由到最合适的检索通道，提高检索准确率。

**验收标准：**

- **Given** 用户输入"化合物 X 的稳定性研究 SOP 要求温度范围是多少？"
- **When** 意图路由模块处理该查询
- **Then** 系统将意图分类为"SOP查询"，并将查询路由至 SOP 文档检索通道

- **Given** 用户输入"ICH Q1A 新药稳定性试验设计要求哪些条件？"
- **When** 意图路由模块处理该查询
- **Then** 系统将意图分类为"法规查询"，并将查询路由至法规文档检索通道

- **Given** 用户输入"今天天气怎么样？"
- **When** 意图路由模块处理该查询
- **Then** 系统将意图分类为"闲聊/越界"，返回友好提示"当前系统仅支持生命科学研发知识查询，请提出与 SOP、法规、实验记录或文献相关的问题"

- **Given** 意图分类置信度低于 0.6
- **When** 意图路由模块处理该查询
- **Then** 系统触发多意图检索，同时在 SOP 和法规通道检索，并在结果中标注可能的意图分类供用户确认

#### US-IR-02：越界问题拦截

**As a** 质量保证专员（QA Lin），
**I want** 系统能识别并拦截与生命科学研发无关的问题，
**so that** 防止系统被滥用，同时避免在无关问题上消耗检索与计算资源。

**验收标准：**

- **Given** 用户输入"帮我写一首诗"
- **When** 意图路由模块处理该查询
- **Then** 系统将其分类为"闲聊/越界"，不执行检索流程，直接返回越界提示

- **Given** 用户输入"推荐一部好看的电影"
- **When** 意图路由模块处理该查询
- **Then** 系统将其分类为"闲聊/越界"，返回越界提示，提示内容包含引导用户提出研发相关问题的话术

- **Given** 用户输入"GMP 对洁净区压差的要求"（边界问题，属于法规/质量查询）
- **When** 意图路由模块处理该查询
- **Then** 系统不将其误判为越界，正确分类为"法规查询"或"GMP 规范查询"

#### US-IR-03：多意图查询处理

**As a** 法规事务专员（Reg Wang），
**I want** 当我的问题同时涉及法规和 SOP 时，系统能同时检索多个知识源，
**so that** 我能获得跨知识源的综合答案。

**验收标准：**

- **Given** 用户输入"NDA 申报的稳定性数据要求是什么？我们的稳定性研究 SOP 是否满足？"
- **When** 意图路由模块处理该查询
- **Then** 系统识别为多意图查询（法规查询 + SOP 查询），同时路由至法规文档和 SOP 文档检索通道

- **Given** 多意图查询的多个检索通道均返回结果
- **When** 答案合成模块整合结果
- **Then** 答案中分"法规要求"和"SOP 要求"两部分呈现，各部分引用对应来源文档

- **Given** 多意图查询中某个通道检索无结果
- **When** 答案合成模块整合结果
- **Then** 答案中明确标注"未在 SOP 库中找到相关内容，仅提供法规要求部分"

### 3.2 混合检索

#### US-HR-01：关键词 + 向量混合检索

**As a** 研发科学家（Dr. Chen），
**I want** 系统同时使用关键词匹配和语义理解来检索相关文档，
**so that** 既能精确匹配 SOP 条款编号等关键词，又能理解我的问题语义找到相关但措辞不同的文档。

**验收标准：**

- **Given** 用户输入包含精确 SOP 编号"QMS-SOP-0142"的查询
- **When** 混合检索模块执行检索
- **Then** BM25 关键词检索精确匹配到该 SOP 文档，且该文档在 RRF 融合结果中排名前列

- **Given** 用户输入"如何处理生产过程中的偏差"（未使用 SOP 原文措辞）
- **When** 混合检索模块执行检索
- **Then** 向量检索通过语义理解匹配到"偏差处理流程 SOP"相关文档，即使查询与文档措辞不完全一致

- **Given** BM25 和向量检索各返回 Top-20 结果
- **When** RRF 融合算法处理两路结果
- **Then** 融合后的排序综合了关键词精确性和语义相关性，两路均命中的文档排名更高

#### US-HR-02：Cross-Encoder 重排

**As a** 质量保证专员（QA Lin），
**I want** 检索结果经过精细重排，最相关的 GMP 条款排在最前面，
**so that** 我能快速定位到最权威、最相关的条款，而非在大量半相关结果中翻找。

**验收标准：**

- **Given** RRF 融合后得到 Top-20 候选文档块
- **When** Cross-Encoder 重排模型对每个候选块与查询进行联合编码打分
- **Then** 重排后的 Top-5 结果中，与查询语义最匹配的文档块排在最前

- **Given** 查询为"EudraLex GMP Annex 1 无菌制剂洁净度要求"
- **When** Cross-Encoder 重排处理候选结果
- **Then** 直接引用 Annex 1 洁净度条款的文档块排名高于泛泛提及无菌生产的结果

- **Given** 重排后 Top-1 结果的相关性分数低于阈值 0.3
- **When** 检索模块输出最终结果
- **Then** 系统标记该查询为"低检索置信度"，触发置信度网关的中低置信度处理逻辑

#### US-HR-03：检索结果元数据透出

**As a** 法规事务专员（Reg Wang），
**I want** 检索结果中包含文档来源、版本号、生效日期等元数据，
**so that** 我能判断引用的法规是否为最新版本，是否具有时效性。

**验收标准：**

- **Given** 检索返回 ICH 指南相关文档块
- **When** 结果元数据组装
- **Then** 每个结果包含文档标题、来源（ICH/FDA/EudraLex）、版本号、生效日期、原文链接

- **Given** 检索到的法规文档存在更新版本
- **When** 结果元数据组装
- **Then** 系统在元数据中标注"存在更新版本：v2.3，生效日期 2026-01"，提醒用户注意版本时效性

- **Given** 用户点击检索结果中的原文链接
- **When** 链接跳转
- **Then** 页面定位到被引用文档块在原文档中的精确位置（章节/段落级别）

### 3.3 带引用的答案合成

#### US-AS-01：答案附带原文引用

**As a** 研发科学家（Dr. Chen），
**I want** AI 生成的答案中每个关键论断都附带知识库原文引用，
**so that** 我能验证答案的准确性，并将引用直接用于实验报告。

**验收标准：**

- **Given** 检索返回 3 条相关 SOP 文档块
- **When** 答案合成模块生成答案
- **Then** 答案中每个关键论断后附带引用标记 [1]、[2]、[3]，对应检索到的文档块

- **Given** 答案中引用标记 [1]
- **When** 用户点击或悬停引用标记
- **Then** 展示引用来源文档的标题、章节、原文片段（前后各 50 字上下文）、文档版本号

- **Given** 答案中某个论断无法在检索到的文档块中找到支撑
- **When** 答案合成模块生成答案
- **Then** 该论断不附带引用标记，且系统在答案末尾标注"以下内容未在知识库中找到直接来源，请人工核实"（若该部分被保留），或直接不生成该部分

#### US-AS-02：答案结构化呈现

**As a** 质量保证专员（QA Lin），
**I want** 答案以结构化格式呈现，包含摘要、详细说明、引用来源列表，
**so that** 我能快速浏览要点，需要细节时再深入查看。

**验收标准：**

- **Given** 查询为"GMP 对无菌生产环境的洁净度等级要求"
- **When** 答案合成模块生成结构化答案

## 4. 功能需求

### 4.1 意图路由模块

#### 4.1.1 意图分类类别

系统支持以下五类意图分类：

| 意图类别 | 代码 | 描述 | 典型示例 | 路由目标 |
|---------|------|------|---------|---------|
| SOP 查询 | `INTENT_SOP` | 查询内部标准操作规程、实验方案、操作指南 | "稳定性研究 SOP 的温度要求" | SOP 文档库 |
| 法规查询 | `INTENT_REG` | 查询 ICH/FDA/EudraLex 等外部法规指南、注册申报要求 | "ICH Q9 质量风险管理要求" | 法规文档库 |
| 实验记录查询 | `INTENT_EXP` | 查询内部实验记录、历史实验数据、ELN 记录 | "上一批次合成实验的收率" | 实验记录库 |
| 文献查询 | `INTENT_LIT` | 查询 PubMed 文献摘要、科研论文、技术文献 | "CRISPR 基因编辑脱靶效应最新研究" | 文献库 |
| 闲聊/越界 | `INTENT_OOB` | 与生命科学研发无关的问题、日常闲聊 | "今天天气怎么样" | 拦截，不检索 |

#### 4.1.2 路由逻辑

**分类器架构**：意图路由模块采用基于大语言模型的零样本/少样本分类器，结合规则增强的后处理。

**路由流程**：

1. **输入预处理**：对用户查询进行清洗（去除多余空格、特殊字符）、语言检测（中英文）、长度检查（过短查询如 < 5 字符触发确认提示）。
2. **意图分类**：将查询送入意图分类器，输出五类意图的概率分布。
3. **规则增强后处理**：
   - 若查询包含 SOP 编号模式（如 `SOP-XXXX`、`QMS-SOP-XXXX`），强制分类为 `INTENT_SOP`。
   - 若查询包含法规名称关键词（如 `ICH Q*`、`FDA Guidance`、`Annex *`），强制分类为 `INTENT_REG`。
   - 若查询包含文献检索特征词（如 `PubMed`、`文献`、`研究进展`），倾向分类为 `INTENT_LIT`。
4. **置信度判断与路由决策**：
   - **单意图高置信度**（Top-1 概率 ≥ 0.7）：路由至单一检索通道。
   - **多意图/低置信度**（Top-1 概率 < 0.7 且 Top-2 概率 > 0.3）：同时路由至 Top-2 意图对应的检索通道，执行多通道检索。
   - **闲聊/越界**（`INTENT_OOB` 概率 ≥ 0.6）：直接返回越界提示，不执行检索。
5. **路由日志**：记录意图分类结果、概率分布、最终路由决策，用于后续分析。

**多语言支持**：意图分类器支持中英文查询输入，对中文查询先进行意图分类（中文模型），对英文查询使用英文模型分类，两者共享同一套五类意图标签体系。

### 4.2 混合检索模块

#### 4.2.1 BM25 关键词检索

- **索引构建**：对知识库所有文档块构建 BM25 倒排索引，支持中英文分词（中文使用 jieba/IK 分词器，英文使用标准 tokenizer）。
- **检索参数**：BM25 参数 k1=1.5, b=0.75（经验默认值，可通过评测调优）。
- **返回结果**：Top-20 文档块，每个结果包含文档块 ID、内容片段、BM25 分数、来源文档元数据。
- **关键词扩展**：支持同义词扩展（如"偏差"→"deviation/OOS/OOT"），基于预构建的生命科学领域同义词词典。

#### 4.2.2 向量检索

- **Embedding 模型**：采用支持中英文的领域微调 embedding 模型（如基于 bge-large-multilingual 或 E5 在生命科学语料上微调），输出 1024 维向量。
- **向量索引**：使用 HNSW（Hierarchical Navigable Small World）索引结构，支持大规模文档的近似最近邻检索，efSearch=128。
- **返回结果**：Top-20 文档块，每个结果包含文档块 ID、内容片段、余弦相似度分数、来源文档元数据。
- **查询向量化**：用户查询经同一 embedding 模型向量化后与文档块向量进行余弦相似度计算。

#### 4.2.3 RRF 融合

- **融合算法**：Reciprocal Rank Fusion（RRF），公式为 `score(d) = Σ 1/(k + rank_i(d))`，其中 `k=60`（经验默认值），`rank_i(d)` 为文档块 `d` 在第 `i` 个检索器结果中的排名。
- **融合输入**：BM25 Top-20 结果 + 向量检索 Top-20 结果。
- **融合输出**：合并去重后的 Top-20 候选文档块，按 RRF 分数降序排列。
- **去重逻辑**：同一文档块的多个检索结果合并，保留最高排名；不同文档块即使内容相似也保留各自条目。

#### 4.2.4 Cross-Encoder 重排

- **重排模型**：采用 Cross-Encoder 架构的重排模型（如基于 bge-reranker-large 或 ms-marco-MiniLM-L-12-v2 在生命科学检索对上微调），对查询和文档块进行联合编码。
- **重排输入**：RRF 融合后的 Top-20 候选文档块。
- **重排过程**：对每个候选块，将 `(query, document_chunk)` 对送入 Cross-Encoder，输出相关性分数（0-1）。
- **重排输出**：按 Cross-Encoder 分数降序排列的 Top-20 文档块，取 Top-5 作为最终检索结果送入答案合成模块。
- **分数阈值**：若 Top-1 的 Cross-Encoder 分数 < 0.3，标记为"低检索置信度"，触发置信度网关的后续处理。

#### 4.2.5 权限过滤

- **过滤时机**：在 RRF 融合之前、BM25 和向量检索返回结果之后，对每个文档块执行权限过滤。
- **过滤逻辑**：根据当前用户角色，查询文档级 ACL，剔除用户无权访问的文档对应的所有文档块。
- **过滤记录**：被剔除的文档块 ID 及原因记录在审计日志中，但不返回给用户（用户不可见被过滤的内容存在）。
- **性能要求**：权限过滤在内存中完成（基于预加载的角色-文档映射缓存），不增加检索延迟。

### 4.3 答案合成模块

#### 4.3.1 答案生成

- **生成模型**：采用支持长上下文的大语言模型（如 GPT-4 级别或同等级开源模型），上下文窗口 ≥ 32K tokens。
- **Prompt 结构**：
  - **System Prompt**：定义角色为"生命科学研发知识库助手"，强调"仅基于提供的检索内容回答，不得编造信息，每个论断需附引用标记"。
  - **Context Block**：将 Top-5 检索结果按编号 [1]-[5] 注入，每条包含文档块内容、来源文档标题、版本、章节定位。
  - **User Query**：用户原始查询。
  - **Output Instruction**：要求输出结构化答案（摘要 + 详细说明 + 引用来源列表），每个关键论断后附 [编号] 引用标记。
- **生成约束**：
  - 答案中出现的任何具体数值、条款编号、日期必须能在检索到的文档块中找到对应原文。
  - 若检索内容不足以完整回答问题，明确标注"以下方面在知识库中未找到相关信息"，不编造补充。
  - 答案语言与用户查询语言一致（中文提问用中文回答，英文提问用英文回答）。

#### 4.3.2 引用标注格式

- **行内引用标记**：答案正文中每个关键论断后附带方括号编号，如"稳定性研究要求温度控制在 25°C ± 2°C [1]"。
- **引用展开**：用户悬停或点击引用标记时，展示引用详情卡片：
  - 文档标题
  - 来源（ICH / FDA / EudraLex / 内部 SOP / 内部实验记录 / PubMed）
  - 版本号 / 生效日期
  - 章节定位（如"Section 3.2, Paragraph 4"）
  - 原文片段（引用处前后各 50 字符上下文，高亮被引用部分）
  - 原文跳转链接（定位到文档对应位置）
- **来源列表**：答案末尾附完整的引用来源列表，按引用编号排列，包含文档标题、来源、版本、链接。

#### 4.3.3 答案结构化

答案按以下结构组织：

```
【摘要】（1-3 句话概括核心答案）
【详细说明】（分点/分段展开，每点附引用标记）
  - 要点 1：xxx [1]
  - 要点 2：xxx [2][3]
  - ...
【对比/表格】（如涉及对比分析，以表格呈现）
【引用来源】
  [1] 文档标题 | 来源 | 版本 | 链接
  [2] 文档标题 | 来源 | 版本 | 链接
  ...
【置信度标签】（高置信度/中置信度）
```

### 4.4 置信度网关

#### 4.4.1 置信度计算方法

系统综合以下三个维度计算最终置信度分数：

| 维度 | 权重 | 计算方式 | 说明 |
|------|------|---------|------|
| 检索置信度 | 0.4 | Top-1 Cross-Encoder 重排分数 | 衡量检索结果与查询的相关性 |
| 覆盖置信度 | 0.3 | 检索到的文档块覆盖查询关键信息的比例 | 衡量检索内容是否足以回答问题 |
| 忠实度置信度 | 0.3 | 答案忠实度评估器得分 | 衡量答案是否忠实于检索内容 |

**最终置信度 = 0.4 × 检索置信度 + 0.3 × 覆盖置信度 + 0.3 × 忠实度置信度**

**忠实度评估器**：使用独立的 LLM 评估器，对生成的答案逐句判定"该论断是否能在检索到的文档块中找到支撑"，输出忠实度分数（有支撑论断数 / 总论断数）。

**覆盖置信度**：通过查询关键实体提取与检索文档块实体匹配比例计算，衡量检索结果是否覆盖了查询中的核心信息需求。

#### 4.4.2 阈值设定与处理策略

| 置信度区间 | 标签 | 处理策略 | 用户可见信息 |
|-----------|------|---------|-------------|
| > 0.75 | 高置信度 | 直接输出答案 | 答案 + 引用 + "高置信度"标签 |
| 0.5 - 0.75 | 中置信度 | 输出答案，顶部附加免责声明 | ⚠️ 免责声明 + 答案 + 引用 + "中置信度"标签 + 建议核实提示 |
| < 0.5 | 低置信度 | 拒答，不输出答案 | 拒答提示 + "提交人工查询"入口 |

**阈值可配置**：置信度阈值（0.75 和 0.5）可在管理后台调整，调整需经过评测验证不引起质量回归后方可生效。

#### 4.4.3 拒答响应规范

低置信度拒答时，系统返回标准化拒答响应：

```
抱歉，当前知识库中未找到足够可靠的信息来回答您的问题。

可能的原因：
- 相关文档尚未入库
- 问题表述需要更具体
- 该问题超出了当前知识库的覆盖范围

建议操作：
① 尝试重新表述您的问题，提供更多上下文
② 联系知识库管理员确认相关文档是否已入库
③ [提交人工查询请求] → 由专家跟进您的问题
```

### 4.5 权限控制

#### 4.5.1 文档级 ACL

- **ACL 数据结构**：每个文档存储一条权限记录，格式为：
  ```
  {
    "doc_id": "DOC-2026-00142",
    "doc_title": "稳定性研究 SOP",
    "accessible_roles": ["R&D", "QA"],
    "owner": "R&D-Knowledge-Admin",
    "classification": "internal",
    "created_at": "2026-01-15T10:00:00Z",
    "updated_at": "2026-03-20T14:30:00Z"
  }
  ```
- **角色定义**：系统预置三类核心角色（研发 `R&D`、质量 `QA`、法规 `RA`），支持扩展自定义角色。
- **默认策略**：文档入库时若未设置权限标签，默认为"不可访问"（deny-by-default），需管理员显式授权后方可被检索。

#### 4.5.2 角色-文档映射

- **映射缓存**：角色-文档映射关系预加载至内存缓存（Redis），检索时直接查缓存，避免每次检索查数据库。
- **缓存更新**：权限变更时触发缓存更新（TTL=5 分钟 + 主动失效），确保权限变更在 5 分钟内全量生效。
- **映射查询**：给定用户角色，返回该角色可访问的所有文档 ID 集合（用于检索时权限过滤）。

#### 4.5.3 检索时权限过滤

- **过滤位置**：在 BM25 和向量检索返回 Top-20 结果后、RRF 融合前执行。
- **过滤方式**：遍历候选文档块，查询其所属文档 ID 是否在当前用户角色的可访问文档集合中，不在则剔除。
- **不可见原则**：被过滤的文档块对用户完全不可见——不出现在检索结果、不出现在答案引用、不提示"存在但无权限的文档"。
- **审计记录**：被过滤的文档块 ID、所属文档 ID、过滤原因（"用户角色 QA 无权访问 DOC-XXX"）记录在审计日志中。

### 4.6 分块策略

#### 4.6.1 固定大小分块（Fixed-Size Chunking）

- **实现方式**：按 token 数量固定切分文档，默认块大小 512 tokens，相邻块之间重叠 50 tokens。
- **参数可配**：块大小（128/256/512/1024 tokens 可选）、重叠量（0-100 tokens 可调）。
- **适用场景**：无明确结构的纯文本文档、短篇摘要、FAQ 条目。
- **局限**：可能在句子或条款中间截断，破坏语义完整性。

#### 4.6.2 句子感知分块（Sentence-Aware Chunking）

- **实现方式**：以句子为最小切分单元，累积句子直至接近目标块大小（默认 512 tokens），在句子边界处切分，重叠区为一个完整句子。
- **分句引擎**：中文使用基于标点（。！？）+ 语义模型的混合分句，英文使用 NLTK/spaCy 句子分割器。
- **适用场景**：文献摘要、技术报告、叙述性文本。
- **优势**：保证每个块包含完整句子，语义连贯性优于固定大小分块。

#### 4.6.3 语义分块（Semantic Chunking）

- **实现方式**：对文档句子逐句计算 embedding 向量，按相邻句子向量的余弦相似度检测语义断点，在相似度下降显著的边界处切分，形成语义内聚的块。
- **参数可配**：相似度阈值（默认 0.5，低于此值视为语义断点）、最小/最大块大小约束。
- **适用场景**：长篇技术文档、综述性文献、内容主题变化丰富的文档。
- **优势**：块内语义高度内聚，块间语义边界清晰，有利于向量检索的语义匹配。

#### 4.6.4 文档结构感知分块（Document-Structure-Aware Chunking）

- **实现方式**：解析文档的结构化标记（Markdown 标题层级、SOP 条款编号如 1.1/1.2/1.2.1、HTML 标签、PDF 章节树），按结构层级切分，每个块保留其所属的章节路径上下文。
- **上下文注入**：每个块的前缀自动注入其结构路径，如块内容为"温度控制在 25°C ± 2°C"，注入前缀为"[SOP-QMS-0142 > 3. 实验条件 > 3.2 温度控制] 温度控制在 25°C ± 2°C"。
- **适用场景**：SOP 文档、GMP 规范、法规指南（ICH/FDA/EudraLex）、结构化操作规程。
- **优势**：保留条款完整性和结构上下文，引用时可精确定位到条款编号，最适合生命科学领域的结构化法规文档。

#### 4.6.5 策略选择建议

| 文档类型 | 推荐策略 | 理由 |
|---------|---------|------|
| 内部 SOP | 文档结构感知分块 | 保留条款编号结构，引用可定位到具体条款 |
| ICH/FDA 指南 | 文档结构感知分块 | 法规文档结构清晰，按章节分块保留上下文 |
| PubMed 文献摘要 | 句子感知分块 | 摘要短且为叙述性文本，按句子分块保留语义连贯 |
| 实验记录 | 固定大小分块 + 语义分块 | 实验记录格式多样，根据结构化程度选择 |
| GMP 规范 | 文档结构感知分块 | 规范条文结构化，按条款分块 |
| 非结构化报告 | 语义分块 | 主题变化丰富，按语义断点分块 |

## 6. 评测体系

### 6.1 评测集构建

#### 6.1.1 评测集规模与覆盖

- **总量**：100 条标注问答（MVP 阶段），后续持续扩充至 300+ 条。
- **意图覆盖**：

| 意图类别 | 条数 | 占比 | 说明 |
|---------|------|------|------|
| SOP 查询 | 25 条 | 25% | 涵盖稳定性研究、合成操作、分析检测等 SOP |
| 法规查询 | 25 条 | 25% | 涵盖 ICH Q 系列、FDA Guidance、EudraLex GMP |
| 实验记录查询 | 15 条 | 15% | 涵盖历史实验数据、批次记录查询 |
| 文献查询 | 15 条 | 15% | 涵盖 PubMed 摘要检索 |
| 闲聊/越界 | 10 条 | 10% | 涵盖无关问题、边界问题 |
| 多意图查询 | 10 条 | 10% | 同时涉及多个意图的复杂查询 |

#### 6.1.2 标注规范

每条评测问答包含以下字段：

| 字段 | 说明 |
|------|------|
| `query_id` | 唯一标识，如 `EVAL-001` |
| `query` | 用户问题原文 |
| `expected_intent` | 预期意图分类 |
| `relevant_doc_ids` | 标注的相关文档 ID 列表（Ground Truth） |
| `relevance_grades` | 文档相关性分级（0=无关, 1=部分相关, 2=高度相关），用于 NDCG 计算 |
| `reference_answer` | 参考标准答案（人工撰写，附引用） |
| `expected_citations` | 预期引用的文档块 ID 列表 |
| `query_language` | 查询语言（zh/en） |
| `difficulty` | 难度等级（easy/medium/hard） |
| `tags` | 场景标签（如"精确匹配"、"语义理解"、"对比分析"、"流程查询"） |

#### 6.1.3 评测集来源

1. **人工编写**（60%）：产品经理与领域专家共同编写，覆盖典型查询场景。
2. **真实查询采样**（30%）：从线上用户查询日志中采样高频/有代表性的查询，经领域专家标注后纳入。
3. **人工查询工单转化**（10%）：从用户提交的人工查询工单中筛选有价值的案例转化。

### 6.2 评测指标定义与计算方法

#### 6.2.1 检索命中指标

| 指标 | 定义 | 计算方法 | 目标值 |
|------|------|---------|--------|
| **Recall@5** | Top-5 检索结果中命中相关文档的比例 | `命中的相关文档数 / 全部相关文档数`，对所有评测条目取平均 | ≥ 0.85 |
| **MRR**（Mean Reciprocal Rank） | 第一个相关文档在检索结果中排名的倒数的均值 | `Σ 1/rank_first_relevant / N`，N 为评测条目数 | ≥ 0.70 |
| **NDCG@10** | 归一化折损累积增益（Top-10），考虑相关性分级和排名位置 | `DCG@10 / IDCG@10`，其中 `DCG@10 = Σ rel_i/log2(i+1)` | ≥ 0.75 |

#### 6.2.2 答案质量指标

| 指标 | 定义 | 计算方法 | 目标值 |
|------|------|---------|--------|
| **引用正确率** | 答案中引用标记指向正确文档的比例 | `正确引用数 / 总引用数`，由人工或自动化校验引用指向的文档是否为相关文档 | ≥ 0.90 |
| **幻觉率** | 答案中无法在检索内容中找到支撑的论断比例 | `无支撑论断数 / 总论断数`，由忠实度评估器自动判定 | ≤ 0.05 |
| **答案忠实度（Faithfulness）** | 答案忠实于检索内容的程度 | `有支撑论断数 / 总论断数`，与幻觉率互补（Faithfulness = 1 - 幻觉率） | ≥ 0.95 |

#### 6.2.3 系统质量指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| **意图分类准确率** | 意图路由分类正确的比例 | ≥ 0.90 |
| **拒答准确率** | 低置信度拒答中确实应拒答的比例（避免误拒答） | ≥ 0.85 |
| **端到端响应时间 P95** | 95% 分位响应时间 | < 8 秒 |

### 6.3 评测流程

#### 6.3.1 离线评测流程

```
1. 准备阶段
   ├── 选择评测集版本（支持多版本管理）
   ├── 确认评测配置（检索参数、模型版本、分块策略）
   └── 初始化评测环境（隔离的索引副本）

2. 执行阶段
   ├── 逐条执行评测问答（意图路由 → 检索 → 答案合成）
   ├── 记录每条结果（检索 Top-10、生成答案、引用列表、置信度分数、耗时）
   └── 并行执行忠实度评估器（LLM-as-Judge）

3. 指标计算阶段
   ├── 检索指标：对比检索结果与 Ground Truth，计算 Recall@5、MRR、NDCG@10
   ├── 答案指标：校验引用正确性（自动化 + 人工抽检），计算引用正确率、幻觉率、忠实度
   └── 系统指标：统计意图分类准确率、拒答准确率、响应时间分布

4. 报告生成阶段
   ├── 总体指标汇总
   ├── 分意图类别明细
   ├── 与历史评测版本对比（指标变化趋势）
   ├── 异常案例分析（指标下降的条目详情）
   └── 评测报告归档（关联代码版本、模型版本、配置参数）
```

**评测频率**：
- 系统每次重大迭代（模型更换、检索参数调整、分块策略变更）后执行完整离线评测。
- 每两周执行一次回归评测（使用固定评测集），确保质量不退化。

#### 6.3.2 在线监控流程

**实时监控指标**：

| 监控指标 | 采集方式 | 告警阈值 |
|---------|---------|---------|
| 日均查询量 | 实时统计 | 突降 > 50% 告警 |
| 响应时间 P95 | 实时统计 | > 10 秒告警 |
| 拒答率 | 实时统计 | > 30% 或环比上升 > 15% 告警 |
| 中置信度比例 | 实时统计 | > 40% 告警 |
| 用户负面反馈率 | thumbs down / 总反馈 | > 20% 告警 |
| 意图分类异常率 | 越界误判率 | > 10% 告警 |

**在线监控看板**：
- 实时查询量趋势图（按小时/天）
- 响应时间分布直方图（P50/P95/P99）
- 置信度分布饼图（高/中/低比例）
- 用户反馈趋势图（thumbs up/down）
- 拒答率与中置信度比例趋势图

### 6.4 分块策略对比实验设计

#### 6.4.1 实验目标

通过控制变量实验，量化对比四种分块策略在不同文档类型上的检索与答案质量表现，为分块策略选型提供数据支撑。

#### 6.4.2 实验设计

**实验变量**：
- 自变量：分块策略（固定大小、句子感知、语义、文档结构感知）
- 控制变量：文档集（固定）、评测集（固定）、检索参数（BM25 k1/b、向量模型、RRF k、重排模型均固定）、生成模型（固定）
- 因变量：Recall@5、MRR、NDCG@10、引用正确率、忠实度、检索延迟、索引大小

**实验矩阵**：

| 实验编号 | 分块策略 | 文档类型 | 评测子集 |
|---------|---------|---------|---------|
| EXP-01 | 固定大小（512 token, overlap 50） | 全部文档 | 全部 100 条 |
| EXP-02 | 句子感知（目标 512 token） | 全部文档 | 全部 100 条 |
| EXP-03 | 语义分块（阈值 0.5） | 全部文档 | 全部 100 条 |
| EXP-04 | 文档结构感知 | 全部文档 | 全部 100 条 |
| EXP-05 | 固定大小 | 仅 SOP 文档 | SOP 相关 25 条 |
| EXP-06 | 文档结构感知 | 仅 SOP 文档 | SOP 相关 25 条 |
| EXP-07 | 句子感知 | 仅文献摘要 | 文献相关 15 条 |
| EXP-08 | 语义分块 | 仅文献摘要 | 文献相关 15 条 |
| EXP-09 | 文档结构感知 | 仅法规文档 | 法规相关 25 条 |
| EXP-10 | 固定大小 | 仅法规文档 | 法规相关 25 条 |

**实验流程**：
1. 对同一批文档分别用四种策略构建独立的向量索引和 BM25 索引。
2. 在相同评测集上运行完整 RAG 流程，记录所有因变量指标。
3. 按文档类型分组分析，对比不同策略在同一文档类型上的表现差异。
4. 生成对比报告，包含指标对比表格、雷达图、分文档类型明细。

**实验报告输出**：

| 策略 | Recall@5 | MRR | NDCG@10 | 引用正确率 | 忠实度 | 检索延迟(ms) | 索引大小(MB) |
|------|---------|-----|---------|----------|-------|------------|------------|
| 固定大小 | 待实验数据填充 | ... | ... | ... | ... | ... | ... |
| 句子感知 | 待实验数据填充 | ... | ... | ... | ... | ... | ... |
| 语义分块 | 待实验数据填充 | ... | ... | ... | ... | ... | ... |
| 文档结构感知 | 待实验数据填充 | ... | ... | ... | ... | ... | ... |

> 注：上表中"待实验数据填充"表示实验执行后由系统自动填入实际数值，非文档占位符。

**决策标准**：
- 若某策略在目标文档类型上 Recall@5 领先其他策略 ≥ 5 个百分点，且忠实度不低于其他策略，则推荐该策略用于该文档类型。
- 若各策略差异 < 3 个百分点，优先选择实现简单、维护成本低的策略（固定大小 > 句子感知 > 语义 > 结构感知）。

## 8. 里程碑与优先级

### 8.1 优先级定义

| 优先级 | 含义 | 交付标准 |
|--------|------|---------|
| **P0** | MVP 必须，无此功能系统不可用 | 核心链路闭环可用，通过基础评测 |
| **P1** | 重要增强，显著提升安全与质量 | 质量保障与安全合规闭环 |
| **P2** | 优化体验，驱动持续迭代 | 评测驱动优化与运维效率提升 |

### 8.2 里程碑规划

#### P0 - MVP（最小可行产品）

**目标**：实现核心 RAG 链路闭环，用户可提交查询并获得带引用的答案。

| 功能模块 | 交付内容 | 验收标准 |
|---------|---------|---------|
| 意图路由 | 五类意图分类 + 单意图/多意图路由 + 越界拦截 | 意图分类准确率 ≥ 0.85 |
| 混合检索 | BM25 + 向量检索 + RRF 融合 + Cross-Encoder 重排 | Recall@5 ≥ 0.80，检索 P95 < 2s |
| 带引用答案合成 | LLM 生成结构化答案 + 引用标注 + 引用展开 | 引用正确率 ≥ 0.85，忠实度 ≥ 0.90 |
| 基础权限控制 | 角色定义 + 文档级 ACL + 检索时权限过滤 | 权限过滤 100% 生效，无越权泄露 |
| 文档入库 | 文档解析 + 固定大小分块 + 索引构建 | 支持 PDF/Word/HTML 解析入库 |
| 基础评测集 | 100 条标注问答 + 基础离线评测脚本 | 评测集覆盖五类意图，评测可一键执行 |

**MVP 交付时间线**：第 1-8 周

| 周次 | 里程碑 |
|------|--------|
| W1-W2 | 架构搭建 + 文档入库管道 + 基础检索（BM25 + 向量） |
| W3-W4 | RRF 融合 + Cross-Encoder 重排 + 意图路由 |

| W8 | 评测验收 + 缺陷修复 + MVP 发布 |

#### P1 - 质量与安全增强

**目标**：建立置信度网关与转人工机制，完善评测体系，满足合规审计要求。

| 功能模块 | 交付内容 | 验收标准 |
|---------|---------|---------|
| 置信度网关 | 三维置信度计算 + 三级阈值处理（高/中/低） | 拒答准确率 ≥ 0.85，无误拒答 |
| 低置信度拒答与转人工 | 拒答响应 + 人工查询工单 + 工单闭环 | 工单全流程可用，管理员可处理并回复 |
| 评测体系完善 | 忠实度评估器 + 引用正确率自动校验 + 评测报告对比 | 评测指标全覆盖，报告含历史对比 |
| 审计日志 | 完整操作日志 + append-only 存储 + 哈希链校验 | 满足 21 CFR Part 11 审计追踪要求 |
| 在线监控（基础） | 实时指标采集 + 监控看板 + 告警 | 拒答率/响应时间/反馈率告警可用 |

**P1 交付时间线**：第 9-14 周

#### P2 - 优化与持续迭代

**目标**：通过分块策略优化和高级权限管理提升系统质量，建立完整的监控运维能力。

| 高级权限管理 | 自定义角色 + 文档分类分级 + 权限审计报告 | 支持自定义角色，权限审计报告可导出 |
| 监控面板（高级） | 用户反馈闭环 + 负面反馈分析队列 + 评测集自动扩充 | 负面反馈 100% 进入分析队列 |
| 多语言增强 | 中英文混合检索优化 + 多语言意图路由 | 中英文混合查询 Recall@5 ≥ 0.80 |
| 性能优化 | 检索缓存 + 查询预处理 + 批量检索优化 | P95 < 6s（较 P1 提升 25%） |
